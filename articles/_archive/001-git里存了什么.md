# 我把一行代码改坏了，git 是怎么给我找回来的

先讲一件真事。

有人改了一个文件，提交了，第二天发现改错了，想回到昨天的样子。他没有备份，也没有网盘——他敲了一行命令，昨天那个版本就回来了。

你可能会想：那不就是存了旧版本吗？

不是。**如果你知道它其实存了什么，这件事就一点都不神奇。** 而且你还会顺便明白另外几个一直困惑你的问题：为什么建分支那么快、为什么 `rebase` 之后提交编号全变了。

这篇就讲这一件事。

---

## 一、先做个实验

随便找个空文件夹，在里面建一个文件，写上两行字，然后在 git 里提交一次。

提交完，打开这个文件夹——你会看到多了一个叫 `.git` 的隐藏目录。

git 全部的秘密都在这个目录里。**你的项目代码和文档，git 一个字节都没备份**；它备份的是这些文件在不同时刻的样子，而这些东西存在 `.git` 里。

再往下走一层，有个 `objects` 目录。里面躺着几个名字很怪的子文件夹，文件夹名是两位十六进制，比如 `8d`，里面的文件名是一长串四十位的字符：

```
8d0e41234f24b0b3ee86960f0d2aa76c5e1b0e3f
```

这个四十位的东西，是**用一个算法根据文件内容算出来的**。同样的内容，永远算出同一个名字；内容差一个字，名字就完全不同。

记住这一点，后面全靠它。

---

## 二、其实只有三个抽屉

git 把所有东西塞进三个抽屉，没有第四种：

| 抽屉 | 装什么 | 一句话记住 |
|---|---|---|
| **文件内容** | 某个文件的全部文字 | 稿纸 |
| **目录清单** | 这个目录下有哪些文件名，各自对应哪张稿纸 | 文件夹的目录页 |
| **提交** | 这次提交用了哪张目录页、上一张是哪张、谁写的、什么时候 | 照片背面写的说明 |

现在有个细节值得停一下：**「文件内容」那个抽屉里，没有文件名。**

同样一段文字，你叫它 `笔记.txt` 还是 `备忘.txt`，存下来的内容抽屉完全一样。名字归**目录清单**管。

这一下就解释了一件事：**在 git 眼里，改文件名根本不叫改。** 你只是把目录页上的一行改了，内容一个字都没动。这就是为什么 `git mv` 快到不像在做事。

---

## 三、`add` 和 `commit`，各做了一半

你平时敲的两条命令，其实分工非常清楚：

**`git add`** —— 把文件当前的内容，算一个名字，存进「文件内容」抽屉。这时东西进去了，但还不算历史。

**`git commit`** —— 生成一张「目录清单」，再生成「提交」那张照片，照片上写着：这是哪张清单、上一张是谁、我为什么改。

就这样。**没有增量、没有差异数据库**，每次提交都是一份完整快照。

那为什么仓库不膨胀？因为内容没变的文件，算出来的名字一模一样，git 不会再存第二份。你改了一百次、每次只动一行，实际存的是一百份小改动加一份公共内容。

---

## 四、分支只是一张便利贴

这条如果早知道，git 的很多命令会立刻顺眼。

`.git` 里有个文件夹 `refs/heads/`，里面每个文件名就是一个分支名。用记事本打开它，内容是**一行四十位的字符**，指向某次提交。

就这么多。一个分支 = 一个文本文件，里面一行字。

所以：

- **建分支** = 新建一个文件，写一行字。这就是它快的原因，快到你根本感觉不到。
- **切分支** = 换一个文件来读，再按那张目录清单把文件摆回工作区。
- **快进合并** = 把当前分支那个文件里的一行字，改成另一个分支的那行字。**没有文件被复制。**

---

## 五、于是三个怪事不再怪

**「为什么提交过的东西改不掉？」**

因为提交的名字就是它内容的指纹。你一改，指纹就变了，它已经不是原来那张照片。这不是 git 不让你改，是这个东西在数学上就没法「原地改」。

**「为什么 `rebase` 之后提交编号全变了？」**

因为 `rebase` 是「把这些改动重新做一遍」。每重做一次就生成一张新照片，新照片的「上一张是谁」变了，指纹自然全变。它不是搬运，是重拍。

**「为什么 `git status` 那么快？」**

因为它不读你的文件内容。它把你的文件重新算一遍指纹，和清单上的指纹比对，对不上就是改了。几万个文件照样一秒。

---

## 六、你现在可以自己验证

在你的项目文件夹里敲这三行（Windows 用 PowerShell）：

```
git log --oneline -1         # 看一眼最新提交的编号
git cat-file -p HEAD         # 看这张「照片」背面写了什么
git cat-file -p HEAD^{tree}  # 看这次提交的「目录清单」
```

第二条会直接吐出那张照片的内容：`tree`（哪张目录清单）、`parent`（上一张照片）、`author`、提交说明。第三条会吐出文件名和对应的那串指纹。

**看到这些，你就不是在「相信」git 了，你是在看它。**

---

## 最后

回到开头那件事：为什么改坏了能找回来？

因为每一次提交都是一张独立存的照片，都在 `.git` 里。你以为的「覆盖保存」，实际上是「每次拍照都留底」。找回来，只是把书签挪回某张旧照片。

理解了这个模型，git 就不再是一堆要背的命令，而是一个**只会往抽屉里放东西、从不删东西的柜子**。你要做的只是知道书签该贴在哪。
