# 你每天早上收到的那条推送，是怎么跑到你手机里的

早上九点，手机响了一下，微信里出现一段文字。你点开读两分钟，然后关掉。

这件事看起来平淡，但中间其实经过了**四台不同的机器、三个不同的公司**。这篇文章把这四步拆开给你看——因为只要看懂一次，你对「互联网怎么运作」的直觉就建立了一半。

## 一、起点：一个文本文件

那篇文章，本质上一个纯文本文件，存在我电脑的一个文件夹里。文件名像这样：

```
articles/books/003-hl-零碎用力.md
```

`articles` 是文件夹，`books` 是栏目，后面是文件名。**它的全部内容就是几百个汉字**，加上第一行的标题和最后一行的小字出处。

没有数据库，没有页面，就是一个 `.md` 文件。

## 二、第一跳：文件被送到 GitHub

我改完文件后，敲一条命令，文件被「推」到 GitHub 上的一个仓库里。

GitHub 是一家美国的代码托管公司。它给你三样东西：**存文件的地方、版本历史、以及一台能替你跑程序的服务器**。

第三样最关键。它意味着——**我的电脑可以关机，程序照样有人跑**。

## 三、第二跳：定时器叫醒了程序

GitHub 里有一条配置，长这样：

```yaml
on:
  schedule:
    - cron: "0 1 * * *"
```

这行 `cron` 的意思是「每天 01:00（UTC）」。UTC 比北京时间晚 8 小时，所以它对应的是**北京时间早上 9 点**。

这里有个常见的误会：**没有人在等这行代码执行**。GitHub 的调度器每分钟扫一次所有仓库的排期表，到点了就把那台虚拟服务器叫醒，跑一遍脚本，然后关掉。

所以你收到的不是「有人按了发送」，而是「一台机器按时开了机」。

## 四、第三跳：脚本把文件变成消息

被叫醒的那台机器上，跑的是我写的一个 Python 脚本。它干四件事：

1. 看看今天是几号、星期几
2. 按排期决定今天该发哪个栏目
3. 从栏目文件夹里按顺序取出一篇
4. 把正文转成一条消息，发给 Server酱

第 4 步值得多说一句。那篇文章是 Markdown 格式（`**加粗**`、空行分段），而微信要的是渲染好的文本。所以脚本会把 Markdown 转成带格式的字符串，再把最后一行的出处变成斜体小字。

**你看到的每条消息，都是在这一刻被「翻译」出来的**，不是原文。

## 五、第四跳：Server酱把它塞进微信

Server酱是一个国内的小服务，作用是**中转**。我给它一个密钥和一段文字，它就通过微信服务号把消息送到关注者的手机上。

为什么要它？因为微信不开放「任何人给你发消息」的能力。只有认证过的服务号能发，而且要走微信的模板消息通道。Server酱做的就是替无数个人开发者跑完这套手续。

它的免费额度是**每天 5 条**——这也是为什么这套系统每天只发两条，且要盯着别超。

## 六、为什么会延迟

你可能会发现，说好的 9 点，有时 9 点零六分才到。原因有层：

**第一层是调度延迟。** GitHub 自己的文档就写着，定时任务不保证准点，高峰期可能推迟几十分钟。它在排队。

**第二层是运行时间。** 服务器从冷启动到跑完脚本，通常十几秒。

**第三层是投递。** Server酱 → 微信服务号 → 你的手机，中间还要过推送通道。

所以「9 点整」从一开始就不是承诺，是**大概**。

## 七、失败长什么样

这套系统最危险的地方，是它**失败的时候可能看起来像成功**。

比如稿件用完了：脚本不会报错，它会安静地发一条「稿件已用完」。比如某天限额超了：消息根本发不出去，但调度器只关心「程序有没有崩溃」，没崩溃就显示绿色的对勾。

**绿色对勾只代表脚本跑完了，不代表消息到了你手上。** 这是所有自动化系统共有的盲区——它监控的是过程，不是结果。

所以我给这套东西加了三道保险：库存预警、失败告警、以及一个「断更」提示。它们的作用不是让系统更可靠，而是**让故障显形**。

## 八、这条链路的一般规律

把这个例子推广开：**任何「自动送达」的系统，都只有三样东西。**

| 环节 | 这里的实现 | 换成别的场景 |
|---|---|---|
| **存储** | GitHub 仓库里的 md 文件 | 数据库、网盘、邮件附件 |
| **触发** | cron 定时器 | 用户点击、别人发消息、传感器报警 |
| **投递** | Server酱 → 微信 | 短信网关、邮件服务器、推送 SDK |

你手机上每一个「自动」发生的事情——外卖状态更新、银行扣款提醒、课程表通知——背后都是这三样东西在接力。

看懂一次，以后遇到任何「为什么我没收到」，你都知道该从哪一环开始查：是内容没生成？是触发没发生？还是投递被拦了？

## 你现在就能验证

如果你用的是安卓手机，打开微信里那条推送，长按它，看看有没有「查看来源」之类的选项。你会看到一条来自「服务号」的消息记录。

再打开浏览器访问 `github.com/easyriver1/daily-life`，看那个仓库的 `Actions` 标签页——那里有每一次运行的记录，包括什么时候被叫醒、跑了多少秒、成功还是失败。

**这两处加起来，就是这条链路的全部真相。**
