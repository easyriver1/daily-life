# 网站存的不是你密码，是你密码的指纹

每隔一阵就有新闻：某网站被拖库，几百万条账号密码流出。

然后大部分人的第一反应是「改密码」。但更好的问题是：**一个正经的网站，凭什么能验证你输对了密码，却不知道你的密码是什么？**

如果你能想明白这件事，你对「密码安全」的理解就超过大多数人。

## 一、最笨也最常见的做法

服务器上有一张表：

| 账号 | 密码 |
|---|---|
| zhangsan | abc123 |
| lisi | woaini520 |

你登录时，它拿你输的密码跟表里比一比，一样就放行。

这个做法的问题一目了然：**只要这张表泄露，所有人的密码就泄露了**。而且不只是这个网站——很多人同一个密码用五个网站，一挂挂五处。

这种表曾经真的很常见，而且现在仍然有。

## 二、换个思路：不存密码，存指纹

密码不该被「保存」，只该被「验证」。于是有人想到：能不能存一个只能验证、不能还原的东西？

能。数学上这个东西叫**哈希函数**。

它的特点是：输入任意内容，输出一串固定长度的字符；而且**不可逆**——给你输出，几乎不可能算出输入。

比如你的密码是 `abc123`，做一次 SHA-256，得到：

```
6ca13d52ca70c883e0f0bb101e425a89e8624de51db2d2392593af6a84118090
```

网站存这串东西。你下次登录再输 `abc123`，它再算一遍，得到同一串，比一比，一样就放行。

**整张表泄露也没关系**——攻击者拿到的是一堆乱码，不知道原始密码是什么。

## 三、但这里有个坑：猜得出来

哈希不可逆，这句话成立的前提是「暴力破解算不过来」。可惜，**常见密码的攻击者根本不用暴力破解**。

因为「密码 → 哈希」这个计算是公开的、极快的。攻击者可以拿一个密码字典（几亿条常见密码），一次性全部算成哈希，做成一张对照表。这叫**彩虹表**。

你那张泄露的表里，只要有一个 `6ca13d52...`，他查表就知道是 `abc123`。

而且算一次哈希只要微秒级。今天一块普通显卡每秒能算几十亿次。

## 四、加盐：让同一密码算出不同指纹

解决办法很朴素：**在哈希之前，给每个用户加一段随机字符串**。这段东西叫「盐」。

```
哈希(盐 + 密码)
```

你的盐是 `kX9#m`，我的盐是 `p2$Qz`。就算我们俩密码都是 `abc123`，算出来的哈希完全不同。

盐和哈希一起存在表里——**盐不需要保密**，它的作用只是让预先算好的表失效。因为攻击者的表是按「无盐」算的，你的盐一加，那几亿条全部作废，他必须针对你这条单独重算。

## 五、还不够：让哈希变慢

加盐解决了「查表」，但没解决「逐条暴力破解」。密码短、字典小的话，照样能在合理时间内算完。

于是又一步：**让哈希函数故意变慢**。

普通的哈希（如 SHA-256）追求快；密码哈希恰恰相反，要设计成计算一次要花几十毫秒。这样攻击者每秒能试的次数从几十亿降到几万，成本上升几十万倍。

这类专用函数有现成的：bcrypt、scrypt、Argon2。**任何正经网站在 2026 年都应该用它们，而不是自己拿 SHA-256 凑。**

## 六、哈希不是加密

这两件事经常被混淆，但区别是根本性的：

| | 加密 | 哈希 |
|---|---|---|
| 能不能还原 | 能（有密钥） | 不能 |
| 用途 | 传输、存储可还原的内容 | 验证内容一致 |
| 类比 | 上锁的箱子 | 指纹 |

网站存密码用哈希，是因为它**永远不需要知道你的密码**——只需要知道「你输的和上次那个是不是同一个」。既然不需要，就不该有能力知道。

反过来，如果一个网站给你发「您的密码是 xxx」的邮件，这只有一个解释：**它存了明文**。这是个危险信号，你应该换掉那个密码，并且以后少用它。

## 七、你能做的事

不用懂算法，只要做三件事：

**第一，重要的账号不复用密码。** 邮箱和支付工具的密码必须是独有的——因为它们是「找回其他所有账号」的钥匙。

**第二，用密码管理器。** 记不住二十个随机密码不是你的问题，是记忆机制的问题。浏览器自带的也行，至少比 `名字+生日+123` 强。

**第三，能开两步验证就开。** 它的价值在于：即使密码泄露，攻击者仍然过不了第二关。而且它防的正是本篇文章描述的那类事故。

## 八、最后

这篇没有一个数字需要你记住，但有一个判断标准值得带走：

**下次看到「某网站被拖库」，先问一句「他们存的是哈希还是明文」。** 如果是加盐的慢哈希，你的密码大概率没用；如果是明文，那才是真麻烦。

这一个问题，就能把「恐慌」换成「判断」。
