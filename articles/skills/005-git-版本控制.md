# 你以为 git 是备份，其实它记的是「为什么改」

大多数人第一次听说 git，理解成「代码的网盘」。不对。

如果只是想存旧版本，你完全可以这样：`论文_v1.doc`、`论文_v2.doc`、`论文_最终版.doc`、`论文_最终版2.doc`。

这套办法的问题不是乱，是**它只记录了「变了」，没记录「为什么变」**。三天后你打开 `最终版2`，根本想不起来改了什么、为什么改。

git 干的事是：每次改动都留一条记录，写清楚**这次改了什么、为什么改**，并且能把任意两个时刻的差异摆在你面前。

它带来三个能力：

1. **回到任何一刻**——不是「回到昨天的备份」，是回到「你写完那一段的那一刻」
2. **看清差异**——这两行是谁改的、什么时候、因为什么
3. **多人并行**——两个人改同一份文件，最后能被合到一起，而不是互相覆盖

第三条是它真正被全世界采用的原因。没有版本控制，五个人改一份文档基本等于灾难。

**今天能懂的一点**：git 的价值不在于「存了文件」，在于它保存了**改动的意图**。这也是为什么提交时要写一句说明——那句话是三个月后的你能读懂的线索。
