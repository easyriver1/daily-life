# 什么是 API：两个程序之间怎么说话

你在手机上点"查看天气"，屏幕上就出现了温度、湿度、明天的预报。

温度不是手机测的，是气象服务商的数据。**手机怎么拿到它？** 中间那一步，就是 API。

## API 是什么

API 全称是应用程序接口。你可以把它理解成**一份约定好的点菜方式**：

- 我做了一个服务，它能回答「北京今天几度」
- 我把"怎么问"写下来：发一个请求，地址是 `…/weather?city=beijing`，格式是 JSON
- 任何人照这个格式发过来，我就返回数据

**API 就是这份"怎么问"的说明书。**

## 为什么需要它

因为程序之间不能"聊一句"，只能严格按格式交换。

如果每个调用方都用自己的格式，服务端就要为每个人写一套解析——五个应用五种写法，维护成本爆炸。

API 把这个成本压到一次：**定义一次格式，所有人照着来**。

这套约定里通常包含三件事：

1. **地址**：问谁
2. **参数**：问什么（城市、日期、单位）
3. **返回格式**：怎么答（JSON，字段名固定）

## 一个你天天在用的例子

你在手机上用微信登录某个小网站，选"用微信登录"，然后授权——这个过程里，那个网站就是在调用微信的 API：请告诉我这个人是谁，并且获取他的昵称和头像。

网站拿不到你的密码，只能拿到微信同意给出的那部分信息。**这就是 API 权限的意义：按约定给，不多给。**

## 一条边界

API 不等于免费公开。

绝大多数 API 需要密钥（key），有的还按调用次数收费，有的限制每分钟能问几次。你看到的"免费天气 API"，通常有每天几百次的额度。

## 今天可以做的

下次看到某个工具说"支持 API"，你就知道它意味着：**这个工具可以被别的程序自动调用，而不只是人在界面上点。**

这就是为什么很多软件加上 API 之后，能接进一整个生态——因为它从"一个网站"变成了"一块可以拼的零件"。
