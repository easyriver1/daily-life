# 什么是编译器：你写的那几十行字，怎么变成能跑的程序

你在记事本里写了一段 C 代码，保存成 `.c` 文件。

双击它——什么都不会发生。因为**文本文件对 CPU 来说毫无意义**。

中间那一步，就是编译器干的活。

## 三样东西，三种语言

| 阶段 | 语言 | 谁听得懂 |
|---|---|---|
| 你写的 | C / C++ / Python | 人 |
| 编译后 | 机器指令（0 和 1） | CPU |
| 中间 | 汇编 | 少数人 |

编译器就是**翻译**。但它不是逐句翻译，而是先整体理解，再重新组织——这也是它能做优化的原因。

## 它其实分了四步

大多数人以为是"一步编译完"，实际是四个阶段：

1. **预处理**：处理 `#include`、`#define`，把你的代码和头文件拼成一个大文件
2. **编译**：把 C 代码翻译成汇编（还只是文本，不是二进制）
3. **汇编**：把汇编翻译成机器码（.o 目标文件，仍然不能直接跑）
4. **链接**：把多个 .o 和库拼成最终的可执行文件

第二步叫"编译"，但整个流程叫"构建"。**你说"编译报错"时，错可能出在任何一步**——比如"undefined reference"就是链接错误，不是语法错误。

## 为什么 C 必须编译，Python 不用

C 是**编译型**：运行前一次性翻译成机器码，运行时直接执行机器指令。

Python 是**解释型**：运行时由解释器一行一行地读、一行一行地执行。

代价很直观：

| | C | Python |
|---|---|---|
| 运行速度 | 快（直接执行机器码） | 慢（每行都要解释） |
| 换平台 | 必须重新编译 | 一般不用 |
| 出错时机 | 编译期就能发现很多 | 只有运行到那一行才知道 |

这也解释了为什么 Python 写起来轻松、跑起来慢——**它是用运行时开销换开发速度**。

## 一条边界

"编译型更快"不是绝对的。

现代 Python 有 JIT、C 有解释器（比如 TCC 边写边跑）。而且程序快不快，主要取决于算法和数据量，不是语言——用 Python 写的对半查找，照样比 C 写的冒泡排序快。

**语言决定的是常数倍，算法决定的是数量级。**

## 今天可以做的

如果你写过 C，下次编译时把 `gcc main.c -o main` 拆开试一次：

```
gcc -E main.c -o main.i     # 只看预处理结果
gcc -S main.i -o main.s     # 生成汇编
gcc -c main.s -o main.o     # 生成目标文件
gcc main.o -o main          # 链接
```

四步跑完，你会看到 `.i` 文件大得吓人——那是头文件全被展开的结果。
