# 什么是缓存：同一个东西，为什么第二次打开就快了

第一次打开某个网页要等三秒，第二次几乎瞬间出现。

你没换网，服务器也没变快。变的是**东西已经在你这边了**。

## 缓存一句话

**把计算结果存到更近、更快的地方，下次直接用。**

它是计算机里最普遍的思想，没有之一——CPU 里有缓存、硬盘有缓存、浏览器有缓存、DNS 有缓存、你脑子里也有。

## 为什么它值得存在

因为访问不同存储的代价差几个数量级：

| 存储 | 大约耗时 |
|---|---|
| CPU 寄存器 | 亚纳秒 |
| 内存 | 几十纳秒 |
| 固态硬盘 | 几十微秒 |
| 网络请求 | 几十毫秒到几秒 |

从网络拿一次数据的时间，够 CPU 算几百万次。

所以只要有一件事被反复用到，把它搬到更近的地方就赚了。

## 关键问题：什么时候该扔掉

缓存真正的难点不是"存"，是"什么时候不信任它"。

如果网页更新了，而你的浏览器还在用旧缓存，你会看到过期内容。如果数据库改了，而系统还在用缓存，用户会看到错误数据。

所以每个缓存都要回答一个问题：**多久之后失效？**

三种常见策略：

1. **定时过期**：存 5 分钟，之后重新拉
2. **主动通知**：数据一变就告诉缓存"作废"
3. **对比版本**：每次先问"还是那一版吗"，是就用缓存

选哪个，取决于你能容忍多旧的数据。**股票行情容忍一秒，天气预报容忍一小时。**

## 一条边界

缓存不能解决所有慢。

如果每次请求的数据都不一样（比如每次搜索的关键词都不同），缓存命中率接近零，加了也没用。

另外缓存会让"第一次慢"永远存在——它优化的是重复，不是首次。

## 今天可以做的

下次觉得某个操作"第一次慢、之后快"，你就知道那是缓存在起作用。

反过来，如果你更新了什么却发现看不到变化——**先怀疑缓存**，这能省掉大量"是不是服务器坏了"的排查。
