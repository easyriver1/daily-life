# 为什么负数要用「补码」表示

计算机只会加法。

它没有专门的减法电路——**减法是用加法做出来的**。

这件事听起来像魔术，实现它的就是补码。

## 先说一个日常的类比

假设一个时钟只有 0 到 11 共 12 个小时。现在指着 3 点，你想调到 1 点：

- 往前走 10 小时（3 + 10 = 13，超过 12 就从 1 开始，落在 1）
- 或者往后退 2 小时（3 - 2 = 1）

**减 2 和加 10，在这个只有 12 个格子的系统里，是同一件事。**

因为 10 = 12 - 2。这个 10，就叫 -2 的"补数"。

## 计算机里的 8 位例子

一个 8 位的数，能表示 0 到 255（共 256 个值）。超过 255 就"溢出"，回到 0。

在这个系统里，-1 可以写成 255 的等价物：

```
  1 = 0000 0001
 -1 = 1111 1111   （也就是十进制的 255）
```

验证一下：`1 + (-1)` 用二进制算：

```
  0000 0001
+ 1111 1111
-----------
1 0000 0000   ← 第 9 位溢出被丢掉，结果正好是 0
```

**减 1 变成了加 255，结果正确。** 计算机只需要一套加法电路，就能同时算加减。

## 代价是什么

一半的取值空间给了负数。

8 位如果只存正数，能到 255；用了补码之后，范围变成 **-128 到 +127**。

这就是为什么 `int`（32 位）的范围是 -2147483648 到 2147483647——**正数比负数的绝对值少一个**，因为 0 占了一个位置。

## 顺带解释两个怪现象

**为什么 `-(-128)` 还是 -128？** 因为 128 超出了 8 位补码的最大值 127，取反加一之后又绕回来了。

**为什么要区分有符号和无符号？** 同样一串 `1111 1111`，按无符号读是 255，按有符号读是 -1。**同一份数据，两种解释。**

## 一条边界

补码不是数学上唯一的方案。历史上还有"反码"和"原码"，但它们有两个问题：-0 和 +0 两个零、减法要额外判断符号。

补码胜出，是因为它把所有情况统一成了一次加法。

## 今天可以做的

如果你学过 C 语言的位运算，试一下：

```c
int a = -1;
printf("%u\n", a);   // 输出 4294967295
```

`-1` 在内存里就是一串全 1。按有符号读是 -1，按无符号读是 32 个 1 组成的最大值。
